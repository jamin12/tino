## 1. 배경

### 현재 상황

신규 앱을 CCP에 온보딩하려면 다음을 사람이 수동으로 해야 한다:

- Gitea 조직 페어(`{org}` + `{org}-cicd`) 준비
- 소스 코드 레포 생성
- 기존 카탈로그 레포(예: `sample-reactnpm-nginx-pipeline`)를 fork/clone
- 모든 yaml 파일을 열어 `sample-reactnpm-nginx`/`sample-cicd` 같은 식별자를 자기 조직·앱 이름으로 일일이 치환
- 짝꿍 GitOps 매니페스트 레포도 동일하게 처리
- 환경별(dev/stg/prd) artifact 레포 깡통으로 만들기

### 문제점

1. **수동 작업 부담** — 앱 하나 추가할 때마다 fork/clone/치환/푸시 반복.
2. **이름 일관성 깨짐** — 한 프리셋 안 수십 개 yaml에 같은 식별자가 반복 등장. 한 군데라도 빠지면 EventListener와 TriggerTemplate이 서로 못 찾는 등 파이프라인이 동작하지 않는다.
3. **레포 세트 누락** — `pipeline` ↔ `gitops` ↔ 환경별 `artifact` 레포가 페어로 동작해야 하는데 누락되는 경우가 잦다.
4. **신규 조직 진입 장벽** — 새 조직에서 처음 쓰려면 `{org}` + `{org}-cicd` 두 조직을 미리 Gitea에 만들어 두어야 한다.
5. **카탈로그 파편화 위험** — 카탈로그 작성자가 회사별/팀별로 식별자 표기를 통일하지 못하면 같은 프리셋도 다른 결과를 낸다.

→ "기술 스택 프리셋을 내 조직의 새 앱에 붙이겠다"는 결정 한 번으로 시스템이 **조직/레포 생성 → 템플릿 복제 → 변수 치환 → 푸시**까지 트랜잭션 처리해야 한다.

## 2. 해결 방향

### 핵심 UX: 5단계 마법사 + 변수 마커 기반 치환

```
1. 조직         소스 조직 선택 또는 신규 (페어 자동)
2. 앱           앱(소스 레포) 선택 또는 신규
3. 프리셋        preset 조직 카탈로그에서 프리셋 선택
4. 플레이스홀더   변수 값 확인/수정 (자동 매핑 + 디폴트)
5. 확인         최종 검토 후 [적용]  ← 여기서 한 번에 트랜잭션 처리
```

### 도메인 모델 (불변 규칙)

```
조직 페어 (항상 1:1)
  {org}            ↔  {org}-cicd
  소스 조직            배포(파이프라인) 조직

레포 세트 (앱 단위 — 한 앱 적용 시 페어로 동작)
  {org}/{appName}                    소스 코드 레포
  {org}-cicd/{appName}-pipeline      파이프라인 정의 (Tekton)
  {org}-cicd/{appName}-gitops        GitOps 매니페스트 (Argo CD 대상)
  {org}-cicd/{appName}-{env}         환경별 artifact (envs 리스트 길이만큼)
                                     예: -dev, -stg, -prd, -qa, -uat ...
```

| 레포 | 분류 | 마법사 처리 |
|------|------|-----------|
| `{appName}` | 소스 코드 | 없으면 빈 레포 생성 |
| `{appName}-pipeline` | pipeline 템플릿 | preset 카탈로그 복제 + 변수 치환 + 푸시 |
| `{appName}-gitops` | manifest 템플릿 | preset 카탈로그 복제 + 변수 치환 + 푸시 |
| `{appName}-{env}` | artifact | **깡통(빈) 레포** 생성. 환경 개수는 4단계 `envs` 플레이스홀더 길이로 결정 |

### 트랜잭션 모델 — Commit-at-End

**1~4단계에서는 어떤 리소스도 실제로 생성되지 않는다.** 사용자가 입력/선택한 값은 마법사 상태로만 보존되며, 실제 Gitea 조직·레포 생성·치환·푸시는 **5단계 [적용] 클릭 시점에 한 번에 수행**된다.

| 단계 | 실제 동작 | 상태 |
|------|---------|------|
| 1 (조직) | Gitea 조회 + 의도 기록 | 아무것도 생성 안 됨 |
| 2 (앱) | 조회 + 의도 기록 | 아무것도 생성 안 됨 |
| 3 (프리셋) | preset 메타 조회 + 선택 기록 | 아무것도 생성 안 됨 |
| 4 (플레이스홀더) | 자동 매핑 + 사용자 수정 입력 받기 | 아무것도 생성 안 됨 |
| 5 (확인) | **[적용] 클릭 시 모든 생성/치환/푸시 수행** | 트랜잭션 커밋 |

## 3. 카탈로그 구조 — preset 조직

### preset 조직 = 카탈로그 자체

```
preset                       ← Gitea 조직 (카탈로그 그 자체)
  ├─ preset-reactnpm-nginx   ← 프리셋 1
  │    ├─ pipeline/          (변수 마커 박힌 Tekton 템플릿)
  │    └─ gitops/            (변수 마커 박힌 K8s 매니페스트)
  ├─ preset-egovmaven-tomcat
  ├─ preset-egovmaven-core
  └─ preset-petgradle-boot
```

- 각 프리셋 = `preset` 조직 안의 1개 레포
- 레포 안에는 **변수 마커가 박힌 템플릿 파일들만** (메타파일 없음)
- 카탈로그 운영자는 이 조직에 새 레포를 추가하기만 하면 카탈로그가 확장됨

### 변수 마커 컨벤션

템플릿 안의 식별자는 모두 **`{{변수명}}` 형태**로 기록된다.

```yaml
# preset/preset-reactnpm-nginx/pipeline/{{env}}/build-pr.yaml (예시)
metadata:
  name: {{appName}}-{{env}}-build-pr
  namespace: {{org}}-cicd
  labels:
    app: {{appName}}
    env: {{env}}
spec:
  params:
    - name: code-repo-org
      value: {{org}}
    - name: code-repo-name
      value: {{appName}}
    - name: app-namespace
      value: {{org}}-{{env}}
    - name: build-script
      value: |
        npm install
        npm run {{buildScriptName}}:{{env}}
    - name: app-image
      value: harbor.cone-chain.net/{{org}}-{{env}}/{{org}}/{{appName}}
    - name: node-version
      value: "{{nodeVersion}}"
    - name: nginx-version
      value: "{{nginxVersion}}"
```

### 환경 통일 컨벤션 — 환경별 차이는 카탈로그가 표현하지 않음

`build-script`, `skip-code-analysis`, namespace 등 환경별로 미세하게 달랐던 값들은 **모두 변수로 통일**한다.

```
[원본 sample 카탈로그의 환경별 차이]    [preset 카탈로그의 통일 패턴]
build-script: npm run build:dev    →    npm run {{buildScriptName}}:{{env}}
build-script: npm run build:stg
build-script: npm run build:prd

skip-code-analysis: false (dev)    →    {{skipCodeAnalysis}}  (단일값)
skip-code-analysis: true (stg/prd)
```

→ 환경마다 다른 동작이 정말 필요하면 **별도 플레이스홀더로 분리**한다 (`{{skipCodeAnalysis}}`).
환경 단위 미세 분기는 카탈로그 작성자가 의도적으로 만들지 않는다.

### 환경 폴더 = 변수 폴더

환경 폴더는 `pipeline/dev/`, `pipeline/stg/`, `pipeline/prd/` 같은 N개로 미리 만들어두지 않고, **`{{env}}/` 한 폴더만** 두며 적용 시 환경 리스트 길이만큼 펼친다.

```
preset-reactnpm-nginx/
  pipeline/
    {{env}}/                        ← env 단위 폴더 (적용 시 N번 펼쳐짐)
      build-cj.yaml
      build-el.yaml
      build-pr.yaml
      build-tt.yaml
      deploy-el.yaml
      deploy-pr.yaml
      deploy-tt.yaml
    kustomization.yaml             (env 리스트 참조)
    gitops-build-el.yaml
  gitops/
    base/
      manifest.yaml
      configmap.yaml
      kustomization.yaml
    overlays/
      {{env}}/                     ← env 단위 폴더
        kustomization.yaml
        ingress.yaml
        patch-cm.yaml
```

## 4. DB — 플레이스홀더 메타

각 프리셋의 **플레이스홀더 정의(이름·라벨·설명·디폴트·타입)**는 CCP DB에 저장한다. 카탈로그 레포에는 두지 않는다.

### 메타 스키마(예시)

```
preset-reactnpm-nginx
  placeholders:
    org:
      label:       "조직"
      description: "namespace, 호스트, 이미지 레지스트리 조직 prefix"
      type:        "text"
      autoFrom:    "step1"               ← 1단계 입력값 자동 매핑
      lockedAtStep4: true

    appName:
      label:       "앱 이름"
      description: "K8s 리소스 이름과 이미지 prefix"
      type:        "text"
      autoFrom:    "step2"               ← 2단계 입력값 자동 매핑
      lockedAtStep4: true

    envs:
      label:       "환경 리스트"
      description: "프리셋이 펼쳐질 환경 (env 단위 N번 렌더링)"
      type:        "stringList"
      default:     ["dev", "stg", "prd"]

    domain:
      label:       "서비스 도메인"
      description: "Ingress 호스트의 도메인 부분"
      type:        "text"
      default:     "cone-chain.net"

    nodeVersion:
      label:       "Node 버전"
      type:        "text"
      default:     "21.1.0"

    nginxVersion:
      label:       "Nginx 버전"
      type:        "text"
      default:     "1.26"

    buildScriptName:
      label:       "빌드 스크립트 이름"
      description: "package.json scripts 항목 (실행: npm run {스크립트}:{env})"
      type:        "text"
      default:     "build"
```

### 메타 운영

- 카탈로그 운영자가 새 프리셋을 등록할 때 CCP 어드민 화면에서 메타를 함께 등록
- 마법사 3단계에서 사용자가 프리셋을 선택하면, CCP가 DB에서 메타를 조회해 4단계 폼을 동적으로 구성

## 5. 화면 설계

### 5-1. 1단계 — 조직 선택 (CCP-PRE-001)

**핵심 UX:** 단일 Combobox 입력란.

- 검색 가능한 단일 입력란 (placeholder: "조직 검색 또는 새로 만들기")
- 입력 시 자동 표시되는 드롭다운 — 두 영역
  - **기존 조직** — 짝꿍 `{org}-cicd`가 페어링된 조직만 노출
  - **새로 만들기** — `+ 새 조직 "{입력값}" 만들기` 옵션. 클릭 시 5단계 적용 시점에 `{org}` + `{org}-cicd` 동시 자동 생성
- 미리보기에 결과 페어를 카드로 시각화

### 5-2. 2단계 — 앱(레포) 선택 (CCP-PRE-002)

**핵심 UX:** 1단계와 동일한 Combobox.

- 상단에 1단계에서 결정된 조직 표시 (고정)
- 검색 가능한 단일 입력란
- 드롭다운
  - **기존 레포** — 선택된 조직 안의 레포 목록. `{org}-cicd/{레포명}-pipeline`이 이미 존재하면 "파이프라인 보유" 뱃지 (선택 시 5단계에서 덮어쓰기 한 번 더 확인)
  - **새로 만들기** — 5단계 적용 시점에 빈 레포로 생성

### 5-3. 3단계 — 프리셋 선택 (CCP-PRE-003)

- 상단 우측에 "preset 조직 · N개 프리셋" 안내
- 카드 그리드: 각 카드에 displayName, 설명, 태그, **플레이스홀더 개수** 표시
- 카드 클릭 시 우측 상세 패널
  - 정의된 플레이스홀더 목록 (DB 메타 기반, 출처 표시: 자동 매핑/디폴트)
  - 템플릿 구조 트리 (`{{env}}/` 변수 폴더 등)
  - 변수 마커 치환 일부 미리보기 (`{{appName}} → shop-front` 등)

### 5-4. 4단계 — 플레이스홀더 확인/수정 (CCP-PRE-004)

**핵심 UX:** 자동 매핑 + 디폴트 + 즉시 미리보기.

- 좌측 폼 / 우측 즉시 미리보기 2단 레이아웃
- 폼 영역
  1. **자동 매핑 영역** — `{{org}}`(1단계), `{{appName}}`(2단계). 자물쇠 아이콘으로 잠겨있어 변경하려면 이전 단계 복귀 필요
  2. **환경 리스트(`{{envs}}`)** — 태그 형태 입력. 디폴트 `[dev, stg, prd]`, 사용자 자유 추가/제거 (예: qa, uat, prod, stress)
  3. **그 외 플레이스홀더** — 카탈로그 작성자가 정의한 변수 (domain, nodeVersion, ...) DB 디폴트로 자동 채움 + 수정 가능
- 우측 즉시 미리보기
  - 현재 값 기준 일부 결과를 즉시 렌더 (`metadata.name`, `host`, `image` 등)
  - 환경별 깡통 레포 리스트도 envs 입력 결과대로 즉시 갱신

### 5-5. 5단계 — 확인 및 적용 (CCP-PRE-005)

- 1~3단계 선택값 요약 카드 (조직 페어 / 앱 / 프리셋)
- **결정된 플레이스홀더 값 표** — 변수 마커, 값, 출처 (1단계/2단계/디폴트)
- **변수 마커 치환 미리보기** — diff 형태 (`{{appName}} → shop-front  38×`)
- **적용 시 처리 순서** 카드 — 단계별 진행 표시기 + skip 뱃지
- [이전] [적용]

**적용 클릭 시 처리 순서 (트랜잭션):**

1. 조직 생성 (필요한 경우 `{org}` + `{org}-cicd` 동시)
2. 소스 레포 생성 (필요한 경우 `{org}/{appName}` 빈 레포)
3. `preset/{선택된 프리셋}` 템플릿 트리를 임시 영역에 복제
4. 모든 파일에서 `{{변수}}` 마커 → 4단계에서 결정된 값으로 치환
5. 환경 리스트(`envs`) 길이만큼 `{{env}}/` 폴더를 펼치기 (env 단위 N번 렌더링)
6. `{org}-cicd/{appName}-pipeline` 레포 생성 + 푸시
7. `{org}-cicd/{appName}-gitops` 레포 생성 + 푸시
8. envs마다 `{org}-cicd/{appName}-{env}` 깡통 artifact 레포 생성
9. 결과 페이지로 이동 (생성된 레포 링크 + 다음 단계 안내)

**진행 표시 / 롤백:**

- 각 단계는 좌측 spinner / check 표시기로 시각화
- 단계가 "기존 활용"인 경우(이미 존재하는 조직/레포 사용) "skip" 뱃지
- 실패 시 즉시 중단 + 결과 페이지에서 사유 + "롤백" 버튼 제공
  - 롤백 범위: 이번 트랜잭션에서 *새로* 생성한 조직/레포만 정리. 기존 자원 미수정.

## 6. 변수 마커 치환 알고리즘

```
입력:
  - placeholders: 4단계에서 결정된 모든 변수의 최종값
  - templateTree: 임시 영역에 복제된 프리셋 파일 트리

알고리즘:

  1. envs 리스트를 제외한 일반 변수를 먼저 치환
     for each text file in templateTree:
       for each [name, value] in placeholders (envs 제외):
         file 내용 = replaceAll("{{" + name + "}}", value, file 내용)

  2. {{env}} 단위 폴더를 envs 길이만큼 펼침
     for each path containing "/{{env}}/" :
       for each env in placeholders.envs:
         (a) 해당 폴더 트리를 복제하여 "/{{env}}/" 부분을 "/" + env + "/"로 변경
         (b) 복제된 트리의 모든 파일에서 "{{env}}" → env 치환

  3. 결과 트리를 사용자 조직 레포로 푸시
```

**왜 안전한가:**

- 마커가 `{{변수}}` 고정 형태라 카탈로그 안의 실제 식별자(`shop-front` 등)와 충돌 불가
- 단순 문자열 매칭으로 일괄 처리 가능 (sentinel·치환 순서·포함 관계 등 고민 불필요)
- 새 프리셋 추가 시 마법사 코드 0줄 변경 — DB 메타에 플레이스홀더만 등록

---

## 7. 예외 / 엣지 케이스

| 케이스 | 처리 |
|--------|------|
| 사용자가 입력한 새 조직 이름이 이미 존재 | 1단계에서 차단 + 메시지 |
| `{org}`만 있고 `{org}-cicd`가 없거나 그 반대 | 조직 페어 위반 — 사용 불가 처리, 카탈로그 운영자에게 정리 요청 |
| 사용자가 선택한 기존 레포에 이미 `{appName}-pipeline`이 있음 | 5단계에서 "덮어쓰기" 한 번 더 확인 |
| 프리셋 템플릿 안의 변수 마커가 DB 메타에 없는 키 | 카탈로그 검증 시 차단 (등록 거부) |
| DB 메타에 있는데 템플릿에는 안 쓰이는 변수 | 4단계에서 노출은 되지만 치환 결과에 영향 없음 (경고 표시) |
| 환경 리스트(envs)가 비어있음 | 5단계 진입 차단 (최소 1개 필요) |
| 사용자에게 조직 생성 권한 없음 | 1단계 새로 만들기 영역 비활성 + 안내 |
| 푸시 실패 (네트워크/권한) | 5단계 결과 화면에서 사유 + "롤백" 옵션 |

## 8. 카탈로그 검증 (등록 시)

새 프리셋을 `preset` 조직에 추가할 때 자동 검증:

```
✓ 템플릿 안 모든 {{변수}} 마커가 DB 메타에 등록되어 있는가
✓ DB 메타의 모든 placeholder가 템플릿에 실제 사용되는가 (경고 수준)
✓ {{env}} 폴더가 pipeline/, gitops/overlays/ 양쪽에 존재하는가
✓ 변수 마커 외에 sample-*/sample 같은 하드코딩된 식별자가 남아있지 않은가
✓ DB 메타에 envs/org/appName 3종은 필수
```

검증을 통과한 프리셋만 마법사 카탈로그에 노출.

## 11. 기대 효과

- **수동 작업 제거** — fork/clone/치환/푸시 일련의 작업이 5단계 마법사로 단축
- **이름 일관성 보장** — 단순 변수 마커 치환이라 누락·오타 위험이 없음
- **조직 페어 자동화** — `{org}` ↔ `{org}-cicd` 페어 규칙을 시스템이 강제
- **카탈로그 확장 용이** — 새 프리셋은 `preset` 조직에 레포 추가 + DB 메타 등록만 하면 동일 마법사로 적용 가능. 마법사 코드 수정 0줄.
- **회사별 환경 명명 자유** — `dev/stg/prd` 표준이 아니어도 `{{envs}}` 입력으로 자유롭게 (qa, uat, prod 등)
- **카탈로그 작성자 약속이 단순** — "변수는 모두 `{{}}` 마커로, 환경별 차이는 카탈로그가 표현하지 않음" 두 줄로 충분
